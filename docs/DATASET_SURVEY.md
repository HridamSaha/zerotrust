# Dataset Survey for Continuous Session-Risk Assessment

**Purpose:** Determine whether a public dataset supports the features and labels required by this project before generating synthetic demonstration data.

**Decision date:** Phase 4 implementation  
**Primary research task:** Detect suspicious *post-authentication* behavioral change within an active session, then map risk to adaptive Zero-Trust decisions.

---

## Required data properties

| Property | Why needed |
|----------|------------|
| Session or time-ordered event streams per user | Continuous reassessment after login |
| Behavioral / contextual attributes (rate, device, resource sensitivity proxies, failures) | Feature engineering for LightGBM + sequence model |
| Labels for normal vs suspicious (or red-team ground truth) | Supervised training and PR-AUC / recall evaluation |
| Ability to form train/val/test splits without user or session leakage | Valid protocol |
| Support for *behavioral drift* within a session or over time | Contribution A |

---

## Candidates evaluated

### 1. LANL Comprehensive Multi-Source Cyber-Security Events (Cyber1)

- **Source:** https://csr.lanl.gov/data/cyber1/
- **Content:** ~58 days of Windows/AD authentication, process, DNS, and flow events; red-team file as compromise ground truth.
- **Fit:** Strong for authentication-graph anomaly research; real enterprise logs.
- **Gaps for this project:**
  - No explicit application-session abstraction aligned with our Zero-Trust API sessions.
  - Missing device-trust, resource-sensitivity, and policy-decision fields used by our enforcement engine.
  - Large download / access workflow; heavy ETL outside undergraduate demo scope.
- **Verdict:** Relevant reference corpus; **not used as the training set** for the runnable demo.

### 2. LANL User–Computer Authentication Associations

- **Source:** https://csr.lanl.gov/data/auth/
- **Content:** ~9 months of successful user→computer authentications only.
- **Gaps:** No failure events, no red-team labels, no session context beyond (time, user, computer).
- **Verdict:** Unsuitable for supervised continuous risk scoring.

### 3. CERT Insider Threat Test Dataset (r4.2 / r5.2 / r6.2)

- **Source:** CMU SEI CERT (commonly redistributed; derived feature packs e.g. TRACE-IT on IEEE DataPort).
- **Content:** Synthetic organizational logs (logon, device, file, email, web) with insider scenarios.
- **Fit:** Useful for insider-threat *day-level* or multi-channel behavior research.
- **Gaps:**
  - Scenario labels are often user-day or scenario-oriented, not fine-grained Zero-Trust *access-decision* labels.
  - Does not natively include our risk-policy outputs or calibrated 0–100 session risk scores.
  - Still synthetic — cannot be claimed as real-world validation.
- **Verdict:** Closest public analog for behavioral anomaly learning, but **schema mismatch** with this framework’s session-event + policy pipeline. Not adopted for Phase 4 training without a large mapping layer.

### 4. CIC-IDS2017 / CIC flow datasets

- **Source:** https://www.unb.ca/cic/datasets/ids-2017.html
- **Content:** Labeled network flows / PCAPs for intrusion detection.
- **Gaps:** Network-centric, not continuous *user-session access control* after application authentication.
- **Verdict:** Out of scope for the stated research contribution.

---

## Decision

**No public dataset cleanly provides** (a) authenticated application sessions, (b) the contextual features our policy engine consumes, and (c) labels for post-login behavioral drift suitable for a compact local demo.

Therefore Phase 4 uses a **documented synthetic session-event dataset** generated by `ml/generate_synthetic.py`.

### Honest limitations of the synthetic set

- Results support **functional demonstration and preliminary method comparison only**.
- They are **not** real-world operational validation.
- They must **not** be compared numerically to published scores on LANL/CERT/CIC as if tasks were identical.
- Generation rules are multi-factor so the label is **not** a trivial function of a single leaked column.

### What the synthetic set *does* enable

- Reproducible train/val/test splits by `session_id` / `user_id`.
- Normal sessions, suspicious sessions, and **within-session drift** windows.
- Shared feature schema for rule baseline, LightGBM, GRU, and hybrid fusion (Phases 5–6).
- Direct wiring into the FastAPI risk engine (Phase 7).
